# The Comseg build of Comskip

Comseg runs stock [Comskip](https://github.com/erikkaashoek/Comskip) (GPL-2.0) for finished recordings. For recordings still being written it needs two changes, which live in the [kontell/Comskip](https://github.com/kontell/Comskip) fork:

- Branch `comseg` is what to build: upstream master plus both changes. `tools/build-comskip.sh` clones it, builds without the SDL GUI and installs the binary under a prefix of your choosing; point the plugin's "Comskip executable" setting at it.
- Branch `live-master-interval` carries the change as one commit on top of upstream master, and [pull request #1](https://github.com/kontell/Comskip/pull/1) on the fork is where it is being readied for upstream.
- Branch `live-tv-follow` carries the second change on top of upstream master, and [pull request #3](https://github.com/kontell/Comskip/pull/3) on the fork is where it is being readied for upstream.

The change adds the ini key `live_master_interval`. In `live_tv=1` mode, every `live_master_interval` seconds of content the process forks; the child runs Comskip's full commercial analysis (`BuildMasterCommList`) over the frames decoded so far, on its own copy of the process state, and writes the result atomically to `<base>.master.edl`. The parent keeps decoding, untouched. It is needed because Comskip's own live list only clusters black frames: on a feed whose ad breaks have no black frames it reports almost nothing while the full analysis, which also uses logo and aspect-ratio changes and silence, finds every break.

The second change adds the ini key `live_tv_follow`. Stock Comskip, on reaching the end of a file that is still being written, closes it, sleeps four seconds, reopens it and seeks back to where it was. In a transport stream that seek is to a byte position worked out from the average bitrate, and when the bitrate varies it can land after the frame it was looking for; everything in between is then never analysed. On 44 minutes of a rugby broadcast read through the plugin's scaled copy as it was recorded, this lost 7 to 8% of the frames, in gaps of up to a minute, and the analyses made from what was left reported a break in the programme and missed real ones. With `live_tv_follow=1` the file is opened in FFmpeg's follow mode instead: a read at the end of the file waits for more data, for up to four seconds times `live_tv_retries`, and nothing is reopened. The plugin sets the key for every live run; a build without the change ignores it.
